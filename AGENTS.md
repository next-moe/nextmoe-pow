# Project Guidelines

Everything in this repository is written in English: code, comments, docs, commit messages. There is no contributing guide, by design.

## Iron rules

1. **No background gradients in any UI.** Use solid colors. The widget exposes its colors, radius and spacing as CSS custom properties, so each site maps them to its own tokens.
2. **The widget does not depend on KunUI or any framework.** `<nextmoe-pow>` is a plain Web Component. Each site writes its own thin Vue/React wrapper.
3. **`testdata/vectors.json` is the contract.** Rust, Go and the WASM solver must all pass it. It is generated by `cargo run -p nextmoe-pow --example vectors > testdata/vectors.json`, never edited by hand, and CI fails when it is stale. A change to the wire format or the hashes bumps the version byte in `docs/protocol.md` and in all three implementations.
4. **Report only measured numbers.** Performance claims (solve times, verify cost, WASM size) come from a run you actually did, on hardware you describe by class and core count. Do not report a number you reasoned about as if you had observed it, and if one turns out to be wrong, retract it explicitly.
5. **Never name a device or chip model.** Not in code, docs, benchmark reports, file names or commit messages. Describe hardware by tier instead (flagship / mid-range / entry phone, 16-core x86 desktop). Benchmark reports do not record the user agent.
6. **One task = one session, and every path has exactly one writer.** On a shared checkout: no branch switch, reset, rebase, merge, clean or stash, and commit with explicit paths (`git commit -- <paths>`), never `add -A`.

## Engineering principles

1. Keep each source file under ~500 lines where practical; past ~300 lines, consider splitting it.
2. TypeScript: write every function as an arrow function.
3. Flutter library code uses the widgets layer only (no Material); the example app may use Material. `flutter/lib/src/rust/` and `flutter/rust/src/frb_generated.rs` are generated: rerun `flutter_rust_bridge_codegen generate` in `flutter/`, never hand-edit.
4. Balance modularity against necessary duplication case by case. The three implementations of the protocol are deliberate duplication, and the vectors keep them honest.
5. Do not let elegance make code hard to follow, and do not write over-defensive code. The verifier trusts what its own key signed.
6. After every change, check for side effects in the other two languages.

## Comments

**Default: none.** Code that can be understood by reading it gets no comment.

A comment is earned by a mistake that already happened, not by one you predict. It records the wrong conclusion that someone actually reached, so the next reader does not reach it again. Standing exceptions:

- A constraint that is true but invisible from the file: a spec rule, an upstream bug, a required ordering, a measured platform fact.
- A completeness assertion over a hand-maintained list.

Write the conclusion, not the mechanism. Never write restatements of the code, section banners, a `TODO` without an owner, or doc comments that only echo the identifier. Machine directives (`//go:build`, `eslint-disable`, …) and generated files are not comments, so leave them alone. Keep comments short. When in doubt, delete it.

## Layout

```
crates/core       Rust reference: challenge format, solver, verifier, criterion benches, vector generator
crates/wasm       wasm-bindgen bindings → packages/solver/wasm (build output, not committed)
packages/solver   @nextmoe/pow-solver: worker pool that spreads sub-puzzles across Web Workers
packages/widget   @nextmoe/pow-widget: <nextmoe-pow> Web Component (docs/widget.md)
go/               github.com/next-moe/nextmoe-pow/go: Issue / Verify / VerifyOnce; cmd/powdemo is the dev server
demo/             demo page for the widget, served by powdemo at /demo/
flutter/          nextmoe_pow Flutter FFI plugin (flutter_rust_bridge + cargokit), example/ app (docs/flutter.md)
bench/            browser benchmark page; results/ holds the raw reports
testdata/         shared vectors
docs/             protocol.md (wire format), m0-benchmark.md (measurements), widget.md, flutter.md
```

## Commands

```sh
cargo test && cargo clippy --all-targets -- -D warnings
cargo bench -p nextmoe-pow
(cd go && go vet ./... && go test ./... && go test -run '^$' -bench Verify)
pnpm install && pnpm build:wasm && pnpm build && pnpm typecheck && pnpm test
scripts/check.sh   # vectors, WASM size budget, all unit tests
scripts/e2e.sh     # widget end-to-end tests in system Chrome against powdemo (POW_BROWSER=firefox for Firefox)
scripts/flutter-check.sh   # Flutter analyze + tests, native solve verified by powdemo
```

The Go module is imported by nextmoe-infra, so keep its `go` directive no newer than infra's toolchain and keep its dependencies to `golang.org/x/crypto`. Replay storage is an interface (`ReplayStore`) so the module does not pull in a Redis client.
